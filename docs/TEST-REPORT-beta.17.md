# 2.0.0-beta.17 测试与发布记录

## 目的

2026-11-09 复查六站询盘时，beta.16 之后还有三个丢系列的场景：

1. 访客在广告落地页的脚本跑完之前就点走了（通衢 N937、荣丰 N389）。落地页没有记录，也没有给链接加代码，第二页只能当成直接访问。
2. Bricks 不刷新翻页后提交（华旌 N7311）。地址栏已变成 `/page/2/`，前端交的页面路径和实际路径对不上，服务端不采用，来源标成直接访问。
3. 未同意 Cookie 的访客提交后再次提交。跳转感谢页时没带代码，后面的页面都没有系列。

## 变更

**`form-context.js`**
- 页面自身没有系列代码、也没有 `#xi=` 时，从站内上一页的地址（`document.referrer`）读取系列代码。只读系列结构代码，不读点击编号，不接受其他网站的地址。
- 提交时 `_request.landing_ad_url` 的路径跟随当前地址栏，这样不刷新翻页后服务端能对上。
- `.brx-ajax-pagination` 里的翻页链接不加 `#xi=`。翻页不刷新文档，加了会留在地址栏。

**`conversions.php`**
- 访客未同意时，跳转感谢页的地址后面带上 `#xi=<系列代码>&t=<时间>`。代码取自本次来源记录的落地网址，去掉所有点击编号。已同意的访客、没有系列代码的询盘不加。

**其他**
- 版本 `2.0.0-beta.17`。
- 以下部分未改动：转化回传、同意判定、小满同步、编号。

## 华旌试运行（2026-11-09）

部署方式：临时 mu-plugin `xi-beta17-trial.php`，加上 `mu-plugins/xi-beta17-trial/form-context.js`（sha256 前缀 `9eaed5e87b596f11`），只在 `XI_VERSION` 为 beta.16 时生效。服务端的感谢页片段不在试运行范围内，只有单元测试。

用华旌真实页面的 HTML 和候选脚本，在本地 jsdom 里模拟（未用真实浏览器，Chrome 扩展未连接）：
- 落地页未同意：产品链接带上代码，不带点击编号；不刷新翻页的链接不加。
- 翻页后：`landing_ad_url` 路径为 `/page/2/`，系列保留。
- 带 `#xi=` 的下一页：标记从地址栏移除，A1 有值，A5 为空，不写存储。
- 只有上一页地址：未同意和已同意都能取到系列，数据包里没有点击编号。
- 感谢页带 `#xi=`：标记移除，查询参数保留，下一个链接继续带代码。
- 自然访客（上一页是 Google）：没有系列，不误标。

## 缓存问题（beta.16 遗留，已定位到现象）

华旌实测：`wp litespeed-purge all` 之后，`/excavators/mini-excavator/` 仍命中 LiteSpeed 旧缓存，带广告参数的访问命中的也是这份。再清一次并等待后，82 个页面全部更新；按网址清除能立刻生效。缓存文件是压缩存储的，没有直接查到残留的根因。

由此判断 beta.16 时方威、通衢的广告落地页是同一现象（推断）。

## 发布步骤（待执行）
